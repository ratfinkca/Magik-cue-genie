# Prepared playlists and hardware export

Research snapshot for 16–17 November 2026. This note documents release candidates, acceptance tests, and vendor workflows. Hardware and firmware combinations below still need hands-on verification.

## The handoff to a player

Cue Studio owns ordered playlists, per-track preparation, and rehearsal. The portable export should capture an immutable selection of those preparations and identify exactly which audio version each one belongs to. The vendor desktop app should create and synchronize the device library. A playlist that opens in a desktop app and a playlist that opens with the right pads, grid, and loops on a standalone player are separate milestones.

The first hardware experiment should use one clean Engine DJ export and one exact Mixstream Pro model and firmware, if available. Add rekordbox USB as a second experiment. Treat Serato as a laptop-and-controller workflow. Each experiment uses generated audio and disposable media or a separate test collection. Studio writes its own export files to a chosen staging location. Originals and vendor libraries are outside that write scope.

## Cue, loop, and grid semantics

| Studio preparation | Portable representation | Device mapping to verify |
| --- | --- | --- |
| Reviewed launch point, drop, or other cue | Stable cue ID, label, original-track seconds, role, review state, and an optional requested slot. | A Hot Cue or Serato Cue Point is a launch action. A rekordbox Memory Cue is a recalled reference and has a different control flow. Let the user choose the desired role and slot. Keep editor order and hardware pad assignment independent. [rekordbox manual](https://cdn.rekordbox.com/files/20260409151936/rekordbox7.214_manual_EN.pdf), [Serato Cue Points](https://support.serato.com/hc/en-us/articles/226518228-Cue-Points) |
| Lead-in and target cue | Two identities linked by target ID, with the resolved time and original seconds/beats/bars offset. | A nonnegative lead-in may map to a second marker if slots allow. Hardware import has no verified representation of the link. Negative pre-roll is silent time before sample zero in Studio. Keep it signed in JSON and list it as unmapped for hardware. Clamping it to zero would change the user's timing. |
| Vocal loop | In-time, out-time, review state, and saved/unarmed state. | Export as a stored loop after audition. A pad that starts looping upon recall and a loop that triggers during uninterrupted playback are different behaviors. For instance, Serato DJ Pro 5.0 adds Cue Loops that start on pad press. [Serato Cue Loops](https://support.serato.com/hc/en-us/articles/18050017443087-Cue-Loops) |
| Emergency loop | Store the two endpoints and **requested active** state separately. Preserve the reason the loop passed Studio's observed-grid and late-track checks. | Verify the stored range first. Enable automatic activation in the vendor UI only after verifying it on the chosen device. Engine documents up to eight Active Loops per track and an on-device assignment shortcut that needs physical parameter buttons. rekordbox also distinguishes saved and Active Loops, with playback behavior depending on player support. [Engine Active Loops](https://support.enginedj.com/support/solutions/articles/69000810671), [Engine hardware assignment](https://support.enginedj.com/support/solutions/articles/69000810682-can-you-set-active-loops-on-both-desktop-software-and-engine-dj-hardware-), [rekordbox manual](https://cdn.rekordbox.com/files/20241004105932/rekordbox7.0.4_manual_EN.pdf) |
| Tempo and beatgrid | Store nominal BPM, observed timestamps and method, first supported beat, and any verified tempo or phase changes. Keep displayed estimates, verified downbeats, and user-entered meter separate. | A BPM tag may populate the tempo display with phase still unknown. A first kick may establish pulse phase without establishing beat one of a bar. Serializing a grid requires trustworthy anchor and tempo, plus explicit meter/bar position if the target needs them. Leave an unsupported grid out and show the omission in the worksheet. |

### Slots and XML

The published rekordbox playlist XML uses track IDs and file URIs, playlist nodes keyed by ID or location, `POSITION_MARK` for cues and loop bounds, and `TEMPO` records for grid anchor, BPM, meter, and beat-in-bar. The example mapping in the published spec names Hot Cues A–C as slot values `0–2` and Memory Cue as `-1`. Start the XML fixture within that documented subset and expand it only after round-trip tests for each desktop/player combination. Set Active Loop requests in the vendor UI and track them in the worksheet. Treat track color and per-cue color as separate data, with tests for each supported presentation field. Serato DJ Pro documents up to eight cue points and eight saved loops, with its Cue Loop mode depending on software version. [rekordbox XML format](https://cdn.rekordbox.com/files/20200410160904/xml_format_list.pdf), [rekordbox manual](https://cdn.rekordbox.com/files/20260409151936/rekordbox7.214_manual_EN.pdf), [Serato Cue Points](https://support.serato.com/hc/en-us/articles/226518228-Cue-Points), [Serato Looping](https://support.serato.com/hc/en-us/articles/226513188-Looping)

The Mixstream Pro family has four physical pads per deck with a second bank for Hot Cues and another for Saved Loops. The manual describes Active Loops beginning as playback reaches them and separately documents settings that change a saved pad's behavior when paused. Test both banks, both playback states, and the device's quantize setting. [Mixstream Pro family manual, Pad Modes and Cues/Loops](https://cdn.inmusicbrands.com/Software/ENDJ5/Mixstream%20Pro%2C%20Mixstream%20Pro%2B%2C%20Mixstream%20Pro%20Go%20-%20User%20Guide%20-%20v5.0.0.pdf)

Keep collisions visible in the export review. A lead-in inserted ahead of Cue 3 in Studio should keep its target relationship while the target profile reports whether a pad is free. A full slot bank, unsupported point type, duplicate slot, or unsupported trigger request goes to the worksheet. Assigning a replacement slot or recalling a saved loop automatically changes live behavior and needs an explicit user choice. Keep audition behavior, EQ/FX gestures, and any future transition automation as Studio rehearsal settings until a target profile defines and tests an equivalent.

### Timing and meter

Treat cue times as offsets from the first decoded sample of the **specific** source version. Limit the first hardware fixture to known PCM WAV timing, then verify encoded formats and their decoder offsets independently. Compare an early beat, a midpoint, and a late beat. Tapping the first kick can fix a phase error and still leave late drift. For example, a constant 127.7 BPM grid against a true 128 BPM pulse drifts by about 282 ms after 256 beat intervals, even with the first beat aligned. [Mixxx notes on decoder timing](https://manual.mixxx.org/2.7/en/chapters/library)

Studio's interpolated or pre-roll grid lines are visual estimates. Export review should preserve the distinction between observed pulses, model predictions, and human-confirmed bar markers. A counted four-beat display group cannot establish 4/4 meter or musical bar one. Multi-`TEMPO` or variable grids become a separate target-profile feature after a constant-tempo fixture passes. [rekordbox XML grid fields](https://cdn.rekordbox.com/files/20200410160904/xml_format_list.pdf), [Mixxx beat detection and grid adjustment](https://manual.mixxx.org/2.7/en/chapters/preferences/beat_detection)

## Staging and acceptance milestones

1. **Portable playlist.** Stage ordered `playlist.m3u8`, an export manifest, and existing v1 per-track JSON sidecars. Keep M3U8 a UTF-8 sequence of relative audio paths. Offer a user-selected copy of encoded audio in an `audio/` subfolder for portability. Require resolved output paths to stay within the staging directory and use a fresh destination when a generated file already exists. The manifest records order, byte fingerprints, exact edit identity, original and staged names, and all omission warnings. Include a CSV cue worksheet for manual entry and review. Verify the playlist in a scratch Mixxx collection via its documented Import Playlist workflow. Each vendor import of CSV or M3U8 gets its own compatibility check. [Mixxx playlist documentation](https://manual.mixxx.org/2.7/en/chapters/library)
2. **rekordbox desktop interchange fixture.** Produce XML only in a new staging folder. Resolve its `file://localhost/` URIs against the staged audio on the importing machine. Browser file selection may supply filenames and bytes without an absolute path, so URI resolution may require a path the user provides or a local packaging helper. Validate entities, URI encoding, entry counts, required IDs, decimal times, Unicode, duplicate basenames, different versions of the same title, and missing paths. Import into a separate rekordbox collection from its XML browser and verify track order, the small documented cue subset and loop endpoints. Confirm that a grid row preserves phase with the fixture's known anchor and meter. [rekordbox XML format](https://cdn.rekordbox.com/files/20200410160904/xml_format_list.pdf), [rekordbox XML import in the manual](https://cdn.rekordbox.com/files/20260409151936/rekordbox7.214_manual_EN.pdf)
3. **First Engine standalone profile.** Use Engine DJ Desktop and its documented import/preparation path to bring the staged test set onto a scratch drive. Verify the drive's library on the exact player. If validation requires manual adjustment of active-loop state, carry that step in the worksheet. The profile records app version, player model, firmware, file system, partition scheme, format, and every verified feature. [Engine export guide](https://support.enginedj.com/support/solutions/articles/69000844056-engine-dj-adding-music-and-exporting-to-a-drive)
4. **First rekordbox USB profile.** Export the already verified desktop fixture through rekordbox to a separate scratch drive in the required Device Library generation. Cover both generations separately if the release claims mixed-booth support. [rekordbox USB support](https://rekordbox.com/en/support/usb-export/)
5. **Controller workflow and additional profiles.** Test a staged crate in Serato DJ Pro, close the app, reconnect the drive and controller, and recall the preparation again. A vendor-managed import that writes metadata uses disposable audio copies. Publish each supported capability against the tested version tuple. Unknown hardware can still use the portable bundle and worksheet.
6. **One export job for several targets.** Freeze one playlist revision and generate each selected target's handoff plus a shared compatibility report. Start with separate scratch drives. rekordbox can put its two library generations on the same drive. Test cross-vendor coexistence per model, firmware, and file system before advertising a mixed drive. Check for media path conflicts and run both vendors' synchronization again before approving that combination. [rekordbox dual-library FAQ](https://rekordbox.com/en/support/faq/devicelibraryplus-6/#faq-54573)

Acceptance starts with generated tracks at a known but nonzero first beat, a known tempo change, a countable downbeat accent, opposite-phase stereo, imported Unicode filenames, and two identical titles with different edits. Include more cues than the selected pad bank, signed pre-roll, a positive lead-in, a deliberately missing beat, a saved vocal loop, and a valid late emergency loop. For every candidate profile, inspect the imported marks, audition the beginning/middle/end against known clicks, test loop seams with quantize off and on, then verify pad assignments and actual loop activation on the device after a cold load. Re-exporting or repeating a failed import must leave existing work intact. Check original audio hashes after each experiment. If a test fails, discard the staged export or rebuild only the isolated vendor collection or test drive from its backup.

For initial acceptance, use millisecond-resolution metadata comparison and a listening target of within 25 ms of the known transient on the PCM fixture. Score the same settings after compression independently. Record separate pass criteria for playlist order, cue timing, and loop arm behavior.

### Library migration and streaming references

Start with UTF-8 M3U8 for playlist order and local audio paths, and Apple Music app or iTunes XML for a library or playlist tree. Parse each format into a preview showing playlists, tracks, existing matches, missing audio, and metadata conflicts. Resolve exact file hashes first, then user-mapped source paths. Show ambiguous matches for review, especially extended mixes and remasters. Apple XML carries library information. The referenced media files are supplied separately. [Apple Music playlist and library exports](https://support.apple.com/en-euro/guide/music/mus27cd5060f/mac), [Lexicon Apple Music import](https://www.lexicondj.com/manual/import-apple-music-itunes), [Lexicon M3U import](https://www.lexicondj.com/manual/import-m3u)

Use the opt-in Lexicon Local API as a read-only preparation adapter. It exposes track metadata, playlists, cues, and beatgrids. Keep the pairing token on the device and retain source identifiers for reimports. Implement bidirectional rekordbox XML for collections, ordered playlists, `POSITION_MARK` cues and loops, and supported `TEMPO` segments. Verify how the exact destination version imports hot and memory cues, colors, grid offsets, and active loops. Each export should report omissions such as excess pad assignments, Studio-only negative lead-ins, and armed-loop behavior that the adapter cannot carry. [Lexicon Local API](https://www.lexicondj.com/docs/developers/api), [rekordbox XML developer guide](https://rekordbox.com/en/support/developer/), [rekordbox XML field reference](https://cdn.rekordbox.com/files/20200410160904/xml_format_list.pdf)

Treat Apple Music and SoundCloud streaming entries as provider references. With user consent, catalog and playlist integrations can support set discovery and help the user link references to their local audio. SoundCloud tracks with a creator-enabled file download can enter the normal local workflow. Consult the services about access for DJ playback, offline handling, audio analysis, and separation before implementing a streaming deck. USB export uses separately acquired, locally playable audio. [Apple MusicKit](https://developer.apple.com/musickit/), [SoundCloud downloads](https://help.soundcloud.com/hc/en-us/articles/115003448787-Downloading-tracks), [SoundCloud API terms](https://developers.soundcloud.com/docs/api/terms-of-use), [rekordbox streaming restrictions](https://rekordbox.com/en/support/faq/streaming-7/#faq-q700188)

### Connected folders and cloud drives

Today, folder import makes a local snapshot and records relative paths for browsing. Save versioned JSON backups to a chosen desktop sync folder. On another device, restore a chosen snapshot, then import the original audio to relink by fingerprint. Pin the tracks for offline use and wait for the provider to finish downloading them before analysis or performance. Keep the live index, browser storage, and generated stems on the device. [Google Drive streaming and mirroring](https://support.google.com/drive/answer/13401938?hl=en), [Dropbox offline files](https://help.dropbox.com/sync/access-files-offline), [OneDrive Files On-Demand](https://support.microsoft.com/en-us/onedrive/save-disk-space-with-onedrive-files-on-demand-for-windows), [Box offline content](https://support.box.com/hc/en-us/articles/360043697574-Making-Content-Available-Offline)

Add folder rescans before direct account connectors. A rescan should detect added, changed, moved, and missing audio. A provider adapter can later access user-selected file IDs, track source revisions, and verify complete local copies before decoding. Use separate permissions for reading selected audio and writing backups. Multi-device edits need stable cue and playlist IDs, a common revision, and reviewable conflicts. [File System Access specification](https://wicg.github.io/file-system-access/), [Google Drive file scopes](https://developers.google.com/workspace/drive/api/guides/api-specific-auth), [Dropbox permissions](https://docs.dropboxapi.com/dropbox-api/docs/oauth), [Microsoft Graph file download](https://learn.microsoft.com/en-us/graph/api/driveitem-get-content?view=graph-rest-1.0), [Box file download](https://developer.box.com/reference/get-files-id-content)

## Local analysis and stems

The local analyzer can use a bounded PCM copy for browser-decodable sources above the 100 MiB direct-analysis request limit. It tries independent low-frequency kick timing when the full-mix evidence fails to establish pulse phase. Those kicks still need consistent track-wide coverage and timing before producing observed beats. Tempo-only results remain a useful outcome. Review an exact edit before overriding a credible tag or assigning a downbeat.

- **First offline model experiment.** Run Beat This `small0` on the full mix as a second opinion for beats and downbeats. The project documents roughly 8.1 MB of weights for `small0` and 78 MB for `final0`, with the PyTorch runtime installed separately. A reproducible baseline is `beat_this sample.wav --model small0 --gpu=-1 -o sample.beats`. Use a local pinned checkpoint for application integration, because the default loader can fetch it. Compare CPU and CUDA on the target machine and evaluate beat phase and downbeats separately. The authors report weaker continuity in some difficult material, so keep unreviewed model positions separate from observed attacks and reviewed export marks. [Beat This repository and models](https://github.com/CPJKU/beat_this#available-models), [Research paper](https://arxiv.org/abs/2407.21658), [PyTorch installation](https://pytorch.org/get-started/locally/)
- **Try stems where the full mix remains ambiguous.** A local Demucs baseline on the same decoded fixture is `python -m demucs.separate -n htdemucs --two-stems=drums -d cpu -o scratch sample.wav`. Use `-d cuda` with compatible PyTorch and graphics hardware, and cache the verified model weights in the setup step. `--two-stems` reduces output files and still performs the underlying full separation. Meta's repository is archived, so pin the version and validate the Windows decoder/runtime combination before relying on it. Compare the drum stem's transients with the original timeline before using them as cue evidence. Validate stem duration/alignment and treat newly prominent bleed as possible false kicks. Existing YAMNet can continue as a lightweight vocal-activity hint and proposed vocal loops remain unarmed until auditioned. [Demucs release](https://pypi.org/project/demucs/4.0.1/), [Demucs usage and archive](https://github.com/facebookresearch/demucs#separating-tracks), [Studio vocal setup](../studio-vocals.md)
- **Vendor stems on standalone hardware.** Engine's documented hardware-stems route pre-renders in Engine DJ Desktop, then uses Sync Manager and a compatible, appropriately unlocked device. Use local drum WAVs as analysis inputs. Verify hardware stem packaging, feature entitlement, and model support through the vendor workflow. [Engine Stems](https://enginedj.com/stems)
- **Keep playback on Web Audio.** Cue Studio already uses AudioWorklet for real-time playback effects such as Key Lock. Run model inference in the existing local Python worker and schedule it as an optional offline job so the deck worklet can keep rendering uninterrupted. For an installed app, a native shell such as Tauri can bundle an analyzer sidecar while retaining the same interface. A browser-only ONNX/WebGPU path is a separate experiment after checking model conversion, supported operations, memory, and CPU fallback against the Python baseline. [Web Audio specification](https://www.w3.org/TR/webaudio/), [Tauri sidecars](https://v2.tauri.app/develop/sidecar/), [ONNX Runtime WebGPU](https://onnxruntime.ai/docs/tutorials/web/ep-webgpu.html)

For a release decision, compare full-mix baseline, trained full-mix model, and optional drum-stem evidence on the same annotated tracks. Record beat and downbeat accuracy, alignment drift, abstention, useful cue placement by listening, false active loops, wall time, peak memory, and playback stability on Windows CPU and any available GPU. Cache results by audio fingerprint, analyzer/model version, and runtime settings. Keep a way to correct the first beat and re-audition questionable transitions in Studio before exporting them.

For deck isolation, precompute and cache a synchronized vocals, drums, bass, and other set. Bind the four deck toggles to gains on sources sharing a single playback clock, cue offset, loop boundary, and tempo. Use the original full mix during ordinary playback. When isolation is active, test alignment through seek, loop wrap, and Key Lock, and check level jumps when switching back to the full mix. Validate memory with stems loaded on both decks and defer separation while both decks are playing if concurrent jobs cause dropouts. [Demucs four-stem output](https://github.com/facebookresearch/demucs#separating-tracks), [Web Audio specification](https://www.w3.org/TR/webaudio/)
